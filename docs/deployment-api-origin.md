# Development API and OAuth origins

The parent development deployment used the fixed API origin `https://repsdev31.ue.r.appspot.com`. Email MVP commit `938de04` changed it to `REACT_APP_API_BASE_URL || "http://localhost:8080"`. The inspected public bundle `/static/js/main.68b81f10.js` has no API build-variable value and consequently starts Google login against localhost. This is the first browser navigation, before Spring Security or Google callbacks.

The shared resolver now preserves any explicitly configured safe HTTPS backend origin, uses the verified App Engine origin on exactly `repsdev.vercel.app` when the build variable is absent, and keeps the localhost fallback only for loopback frontend hosts. Other deployments/previews must configure an HTTPS backend origin. A deployed build configured to use loopback or an unsafe URL fails explicitly instead of directing authentication there. Neither query parameters nor browser-supplied redirect targets select the backend.

In the Vercel project serving `repsdev.vercel.app`, set or verify `REACT_APP_API_BASE_URL=https://repsdev31.ue.r.appspot.com` for the actual deployment environment. A project's `vercel.app` main domain normally uses its Production environment even when the project is named development; setting only Vercel's Development environment does not configure that hosted build. CRA embeds this value during build, so a later owner-triggered rebuild is needed to change it. No Gmail secret, key or feature flag belongs in Vercel.

Desktop and mobile Google initiation and all existing API clients share `baseUrl`. Gmail completion uses relative frontend route `/account/gmail/callback` and calls authenticated backend endpoints; the backend chooses the Google callback URI. Logout and authentication-expiration redirects remain relative `/login` on the current frontend. The deployment change does not alter OAuth scopes, state validation, JWT handling or HTTP action-ID interceptors.

Validate after approved deployment: Google login returns through `https://repsdev31.ue.r.appspot.com/login/oauth2/code/google` to `https://repsdev.vercel.app`; failure stays on Vercel; logout stays on Vercel; Gmail Connect/Reconnect returns to `https://repsdev.vercel.app/account/gmail/callback`. Preserve the local callbacks. These deployed browser flows have not been tested by this PR; unit tests and inspection of the previous public bundle are not proof of deployed success.
